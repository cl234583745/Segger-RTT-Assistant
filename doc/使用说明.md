# RTT Assistant - 使用说明

RTT Assistant 是一款图形化的 RTT（Real Time Transfer）调试工具，支持 J-Link、DAP-Link、ST-Link 等多种调试器，提供日志收发、示波器波形显示、变量监视等功能。

---

## 快速上手

1. **启动程序**：双击 `RTT-Assistant v2.1.1.exe`
2. **配置连接**：点击工具栏的 **配置** 按钮，打开连接配置对话框
3. **选择调试器**：在"步骤1"中点击 **刷新**，选择已检测到的探针
4. **选择目标芯片**：
   - J-Link：在"步骤3"的 J-Link 目标设备下拉框中选择芯片型号（如 STM32F407VE）
   - DAP-Link / ST-Link：在"步骤3"的其他 Link 目标设备中选择 PyOCD 目标（如 r7ka8p1kf），列表中没有则点击 **Pack** 按钮下载
5. **设置接口**：在"步骤4"中选择接口为 SWD，速度建议 4000kHz
6. **RTT 控制块**：在"步骤5"中保持默认的"自动检测"即可
7. **点击确定**：等待连接成功，状态栏显示探针信息和绿色"已连接"
8. **收发数据**：接收区自动显示 RTT 数据；发送区输入文本后按 **Enter** 或点击 **发送**

## 连接配置

点击工具栏的 **配置** 按钮，打开"连接配置"对话框。配置过程分为 5 个步骤：

### 步骤1：调试器选择

- 点击 **刷新** 按钮，程序自动探测已连接的调试器
- 探测结果会列出所有探针，格式为 `[类型] 名称 (SN:序列号)`
- J-Link 探针、DAP-Link、ST-Link 都会在此列出
- 选择你要使用的探针

> **注意**：刷新后如未找到探针，请检查 USB 连接和驱动。J-Link 需要安装 J-Link 软件包，DAP-Link/ST-Link 无需额外驱动。

### 步骤2：连接方式

- **USB**：默认方式，通过 USB 连接探针
  - 勾选 **SN/Nickname** 后可输入序列号或昵称，用于在多探针环境下区分指定探针
- **TCP/IP**：通过网络连接远程 J-Link（需 J-Link 支持 Ethernet 功能）
  - 需输入 J-Link 的 IP 地址

### 步骤3：目标设备

根据选择的探针类型，显示对应的配置行：

**J-Link 目标设备：**

- 下拉框中选择芯片型号（如 STM32F407VE、Cortex-M4）
- 下拉框可编辑，可直接输入型号
- **...** 按钮：打开设备型号筛选对话框，可搜索过滤，查看芯片的 Flash/RAM 大小、Core ID 等信息
- **更新** 按钮：从 JLink DLL 重新读取设备列表并保存到 `runtime/devices.txt`

**其他 Link 目标设备（DAP-Link / ST-Link 等 CMSIS-DAP 探针）：**

- 下拉框中选择 PyOCD 目标类型（如 stm32f407ve、r7ka8p1kf）
- 下拉框可编辑，可直接输入
- **...** 按钮：打开 PyOCD 目标筛选对话框，可查看目标来源（builtin 内置 / pack 包安装），来源为 Pack 的条目绿色高亮
- **更新** 按钮：重新扫描所有 CMSIS Pack 文件，刷新目标列表
- **Pack** 按钮：下载 CMSIS Pack。点击后输入芯片型号（如 STM32U575），程序自动从 Keil 官方 Pack 源下载并安装，安装后目标列表中会出现该芯片

> **注意**：DAP-Link/ST-Link 连接前必须确保目标芯片的 Pack 已安装或 PyOCD 内置支持该芯片。

### 步骤4：接口设置

| 参数 | 说明 |
|------|------|
| **接口** | SWD（默认）或 JTAG。绝大多数 MCU 使用 SWD 即可 |
| **速度** | 从 125kHz 到 50000kHz 共 17 档可选。推荐 **4000kHz**，稳定性和速度均衡。高速目标可尝试更高频率，如遇到连接不稳定请降低速度 |
| **连接模式** | under_reset（先复位再连接，默认）、halt_on_connect（连接后暂停）、pre_reset（连接前复位）、attach（直接附着，不暂停）、default（默认行为） |

### 步骤5：RTT 控制块

RTT 控制块是 MCU 内存中存放 RTT 通道信息的结构体，有 4 种定位方式：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **自动检测** | J-Link 自动在内存中搜索 RTT 控制块签名 | 大多数单核 MCU，推荐首选 |
| **地址** | 手动指定 RTT 控制块在 RAM 中的地址 | 自动检测失败时使用 |
| **搜索范围** | 指定 RAM 起始地址和大小，在此范围内搜索 | 多 AP 芯片（如瑞萨 RZ 系列）或 RAM 布局特殊的 MCU |
| **Map 文件搜索** | 解析编译生成的 .map 文件，自动提取 `_SEGGER_RTT` 符号地址 | 每次重新编译后 RTT 地址变化时自动适配 |

**Map 文件搜索使用方法：**

1. 选择"地址"模式
2. 点击 **打开map文件**，选择编译器生成的 .map 文件
3. 点击 **搜索_SEGGER_RTT**，程序自动解析并填入地址
4. 支持 GCC、IAR、Keil 等主流编译器格式

**搜索范围配合使用：**

1. 选择"搜索范围"模式
2. 点击 **获取自动检测地址**，程序根据芯片型号自动填入 RAM 起始地址和大小
3. 也可手动填入起始地址和搜索大小

> **注意**：自动检测失败时请优先尝试"地址"模式，从 .map 文件中获取 `_SEGGER_RTT` 符号地址。

### 确定/取消

配置完成后点击 **确定** 保存并开始连接，点击 **取消** 放弃修改。

## 数据收发

### 接收区

- 显示 MCU 通过 RTT 上行通道发送过来的数据
- 默认以文本方式显示，勾选 **HEX 显示** 切换为十六进制
- 勾选 **时间戳** 可为每行数据添加到达时间
- 开启 **ANSI 染色** 后，RTT 数据中的颜色转义码会渲染为彩色文字
- 开启 **关键字高亮** 后，ERROR、WARNING 等特定词汇自动着色
- 接收区最多保留 1000 行，超出后自动清除最早的显示内容（不影响日志文件）
- 所有接收数据同时写入日志文件 `runtime/log/rtt_data_YYYYMMDD_HHMMSS.log`

### 发送区

- 输入文本后按 **Enter** 发送，**Shift+Enter** 换行
- 支持两种发送模式：

| 模式 | 说明 | 示例 |
|------|------|------|
| **字符串** | 发送 UTF-8 文本，MCU 端以字符串接收 | `AT+OK` → 发送 5 字节 |
| **HEX** | 发送十六进制字节，空格分隔 | `01 02 A0 FF` → 发送 4 字节 |

- 勾选 **加换行** 可在发送内容后自动追加换行符 `\r\n`
- 发送按钮右侧显示已发送字节计数

## 示波器模式

示波器模式用于实时显示 MCU 发送的数值数据，以波形曲线形式展示，类似虚拟示波器。

### 切换模式

点击工具栏的 **模式** 按钮，选择 **示波器** 或 **混合** 模式：

- **日志模式**：只显示 RTT 文本接收区
- **示波器模式**：只显示波形视图
- **混合模式**：上下分栏同时显示文本接收区和波形视图

### 采集控制

| 按钮 | 说明 |
|------|------|
| **开始** | 开始采集数据，按钮变为"停止" |
| **停止** | 停止采集并清空波形画布 |
| **暂停** | 冻结当前画面，后台继续接收数据；按钮变为"恢复" |
| **恢复** | 恢复实时显示 |
| **清除** | 清除所有通道的曲线和数据 |

### 波形显示控制

| 控制项 | 说明 |
|--------|------|
| **时基** | 横轴时间刻度，从 1µs/格 到 500s/格 共 27 档可调 |
| **触发** | 自动（持续显示）、正常（触发条件满足时显示）、单次（触发一次后停止） |
| **配色** | 通道曲线的颜色方案：默认 / 暖色 / 冷色 / 灰阶 |
| **样式** | 绘制样式：线条 / 点 / 线+点 / 矩形 |
| **采样率** | 设置采样频率（Hz），0 为自动估算（尽可能快采样） |

鼠标在波形区域的操作：

- **滚轮**：放大/缩小时基（上滚加速、下滚减速）
- **鼠标悬停**：显示十字光标和当前坐标值 `x=... y=...`
- **右键菜单**：自动范围、重置视图、显示网格开关

### MCU 端数据格式

示波器模式支持三种数据格式：

#### JScope 标准格式（推荐）

MCU 端通过 RTT 通道名声明数据结构。通道名必须以 `JScope_` 开头，后跟字段描述符：

```
JScope_<type1><size1><type2><size2>...
```

字段描述符：

| 描述符 | 类型 | 大小 |
|--------|------|------|
| `t4` | 时间戳（微秒） | 4 字节 |
| `i1` | int8 | 1 字节 |
| `i2` | int16 | 2 字节 |
| `i4` | int32 | 4 字节 |
| `u1` | uint8 | 1 字节 |
| `u2` | uint16 | 2 字节 |
| `u4` | uint32 | 4 字节 |

示例：`JScope_t4i4u1` 表示"4 字节时间戳 + 4 字节 int32 + 1 字节 uint8"，每包 9 字节。

连接成功后，RTT Assistant 自动解析通道名中的格式描述并显示在工具栏的 **格式** 标签中。

#### 自动识别模式

如果通道名不以 `JScope_` 开头，则使用自动识别模式：每个数值前加 1 字节类型标识。

| type_byte | 类型 |
|-----------|------|
| 0x01 | int8 |
| 0x02 | uint8 |
| 0x03 | int16 |
| 0x04 | uint16 |
| 0x05 | int32 |
| 0x06 | uint32 |
| 0x07 | float |

#### 固定格式

手动选择一种固定类型（int8 / uint8 / int16 / uint16 / int32 / uint32 / float），所有数值都按该类型解析。

### 高速模式

程序自动根据数据量切换处理模式：

- **< 2000 样本/秒**：普通模式，主线程直接处理
- **> 5000 样本/秒**：自动切换到高速模式，独立线程 + 30FPS 降采样显示（峰值检测算法）
- 切换过程自动进行，无需用户干预

高速模式缓冲区最大可缓存 1,000,000 个样本，显示时降采样至 2000 个点，确保波形流畅的同时不拖慢界面。

### MCU 缓冲区信息

工具栏的 **MCU 缓冲** 标签显示每个通道的缓冲区大小（如 `CH1=1024B`），鼠标悬停可查看通道名和详细大小。

## 日志窗口

通过工具栏的 **日志 → 系统日志** 打开系统日志窗口。

- 实时显示系统运行日志，每 1 秒自动刷新
- 支持按日志级别筛选：全部 / DEBUG / INFO / WARNING / ERROR / SUCCESS
- 不同级别颜色标识：DEBUG 灰色、INFO 绿色、WARNING 黄色、ERROR 红色、SUCCESS 青色
- **清空** 按钮清除显示内容
- **打开日志文件** 按钮直接打开 `runtime/log/rtt_system.log`
- 日志文件自动轮转，单个文件最大 5MB，保留 3 个备份

## 变量监视器

变量监视器用于实时读取 MCU 内存中指定变量的值。

- **添加变量**：弹出对话框，输入变量名、内存地址（十六进制）、数据类型
- **删除变量**：选中一行后删除
- 表格显示：名称、地址、类型、当前值、更新时间
- 程序按固定间隔（默认 100ms）自动读取变量值并更新显示

支持的变量类型：uint8、int8、uint16、int16、uint32、int32、float

> **注意**：变量监视依赖调试器的内存读取功能，部分探针在高负载下可能响应延迟。

## MCU 端配合指南

### RTT 移植

MCU 端需要移植 SEGGER RTT 代码。基本步骤：

1. 从 SEGGER 官网或程序自带资源（`resources/RTT.zip`）获取 RTT 源码
2. 将 `SEGGER_RTT.c`、`SEGGER_RTT.h`、`SEGGER_RTT_Conf.h` 加入工程
3. 调用 `SEGGER_RTT_Init()` 初始化
4. 编译并下载到 MCU

详细移植步骤请参考程序菜单 **帮助 → SEGGER RTT → 移植文档**。

### 日志模式（通道 0）

通道 0 是 RTT 的默认调试通道，MCU 端无需额外配置，初始化后即可使用：

```c
#include "SEGGER_RTT.h"

// 初始化（通常在 main 开头调用一次）
SEGGER_RTT_Init();

// 发送文本
SEGGER_RTT_WriteString(0, "Hello RTT Assistant!\r\n");

// 格式化输出
SEGGER_RTT_printf(0, "温度: %d°C, 湿度: %d%%\r\n", temp, humidity);
```

通道 0 的数据会显示在 RTT Assistant 的 **接收区**。

### 示波器模式（通道 1）

示波器模式通常使用通道 1（或其他非 0 通道）。MCU 端需要：

1. 调用 `SEGGER_RTT_ConfigUpBuffer()` 配置通道，通道名声明 JScope 数据格式
2. 按声明的格式打包二进制数据后调用 `SEGGER_RTT_Write()` 发送

```c
#include "SEGGER_RTT.h"

// 配置通道1，通道名声明数据格式
// JScope_t4i4u1 = 4字节时间戳 + 4字节int32 + 1字节uint8
SEGGER_RTT_ConfigUpBuffer(1, "JScope_t4i4u1", NULL, 0, SEGGER_RTT_MODE_NO_BLOCK_SKIP);

// 按格式发送数据
void send_data(int32_t value, uint8_t status) {
    uint8_t packet[9];
    uint32_t ts = get_timestamp_us();   // 微秒级时间戳

    *(uint32_t*)&packet[0] = ts;        // t4: 时间戳
    *(int32_t*)&packet[4]  = value;     // i4: int32
    packet[8] = status;                 // u1: uint8

    SEGGER_RTT_Write(1, packet, 9);
}
```

> **注意**：
> - 通道名必须以 `JScope_` 开头，否则会被当作自动识别模式处理
> - 数据包必须严格按通道名中声明的字段顺序和大小排列，否则解析会错位
> - 缓冲区模式建议使用 `SEGGER_RTT_MODE_NO_BLOCK_SKIP`，避免 MCU 因缓冲区满而阻塞
> - 时间戳字段 `t4` 必须放在第一个位置

### 使用 ANSI 彩色输出

RTT 支持 ANSI 转义码，MCU 端可以使用 SEGGER RTT 预定义的颜色宏：

```c
#include "SEGGER_RTT.h"

SEGGER_RTT_WriteString(0, SEGGER_RTT_CTRL_RESET "普通文字\r\n");
SEGGER_RTT_WriteString(0, RTT_CTRL_TEXT_RED "红色文字\r\n");
SEGGER_RTT_WriteString(0, RTT_CTRL_TEXT_GREEN "绿色文字\r\n");
SEGGER_RTT_WriteString(0, RTT_CTRL_TEXT_YELLOW "黄色文字\r\n");
SEGGER_RTT_WriteString(0, RTT_CTRL_TEXT_BLUE "蓝色文字\r\n");
SEGGER_RTT_WriteString(0, RTT_CTRL_BG_RED "红色背景\r\n");
```

RTT Assistant 需开启 **工具 → ANSI 染色** 才能正确显示颜色。

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| **J-Link DLL 找不到** | 将 `JLink_x64.dll`（64位）或 `JLinkARM.dll`（32位）放入 `runtime/dll/` 目录 |
| **DAP-Link / ST-Link 连接失败** | 确认已下载对应芯片的 CMSIS Pack，或在配置对话框中点击 **Pack** 按钮下载 |
| **探针列表为空** | 检查 USB 连接；J-Link 确认已安装 J-Link 软件包；DAP-Link 确认驱动正常 |
| **RTT 初始化失败** | 确认 MCU 已移植 RTT 代码并调用了初始化函数；尝试在配置对话框中使用"地址"模式并填入 .map 文件中 `_SEGGER_RTT` 的地址 |
| **目标芯片列表为空** | J-Link：点击 **更新** 按钮从 DLL 刷新；DAP-Link：点击 **Pack** 按钮下载对应芯片的 Pack |
| **通道数据不显示** | 确认 MCU 发送的通道号与 RTT Assistant 配置一致；可调整配置对话框中的 RTT 控制块模式 |
| **示波器无波形** | 确认 MCU 使用了正确的通道命名格式（`JScope_` 开头）；确认数据包格式与通道名声明一致 |
| **ANSI 颜色不显示** | 确认已开启 **工具 → ANSI 染色** |
| **窗口启动过慢** | 首次启动需要加载设备列表，属正常现象；后续启动会缓存加速 |
| **示波器画面卡顿** | 尝试降低采样率或增大时基；高速模式下程序会自动优化 |

## 注意事项

1. **J-Link 用户**：需要自行安装 J-Link 软件包（V930+），或将 `JLink_x64.dll` 放入软件目录
2. **DAP-Link / ST-Link 用户**：不需要额外驱动，但需要下载对应 MCU 的 CMSIS Pack
3. **首次使用**打开配置对话框时，设备列表加载可能需要几秒钟（异步加载，不阻塞界面）
4. **多探针环境**：可在步骤2中勾选 SN/Nickname 并输入序列号来指定使用哪个探针
5. **示波器缓冲区**：高速模式下缓冲区最大 1,000,000 个样本，过高的采样率仍可能导致数据丢失
6. **日志文件**会持续增长，建议定期清理 `log/` 目录
7. **程序支持暗色和亮色主题**，可在 工具 → 主题 中切换
8. **RTT 数据发送**使用非阻塞模式（`SEGGER_RTT_MODE_NO_BLOCK_SKIP`），建议 MCU 端也使用该模式，避免因缓冲区满阻塞业务逻辑

## 烧录固件

1. **选择固件文件**：点击工具栏的 **配置** 按钮，在配置对话框顶部的"固件文件选择"区域点击 **打开** 选择固件文件（支持 .hex / .bin / .elf / .srec 格式）
2. **多条路径管理**：可以添加多条固件路径，鼠标选中哪条则激活哪条；支持 **替换** 和 **删除** 操作
3. **点击烧录**：点击工具栏的 **烧录** 按钮，弹出烧录进度窗口，实时显示烧录日志
4. **烧录成功**：进度窗口显示绿色"烧录成功"标签，2秒后自动关闭
5. **烧录失败**：进度窗口显示红色"烧录失败"标签，保持打开供用户查看错误信息
6. **路径联动**：选择固件文件后，如果同目录存在同名 .map 文件，RTT控制块的map路径会自动填充；反之亦然
7. **支持的调试器**：J-Link（pylink DLL）、DAP-Link / ST-Link（pyocd）

## 示波器多通道用法

### 方式一：子通道模式（推荐用于同频同相位多通道）

使用单个RTT通道（如CH1），通过JScope合并buffer格式（如`JScope_u4u4`）一次发送所有通道数据。MCU端代码示例：

```c
// 配置通道1为JScope_u4u4格式
static char buf1[1024];
SEGGER_RTT_ConfigUpBuffer(1, "JScope_u4u4", buf1, sizeof(buf1), SEGGER_RTT_MODE_NO_BLOCK_SKIP);

// 定义合并数据结构（1字节对齐）
#pragma pack(push, 1)
typedef struct {
    uint32_t ch1;
    uint32_t ch2;
    // 可以扩展更多通道
} MultiChannelData_t;
#pragma pack(pop)

// 发送数据
MultiChannelData_t data;
temp1 = (temp1 == 100) ? 0 : 100;
temp2 = (temp2 == 90) ? 10 : 90;
data.ch1 = temp1;
data.ch2 = temp2;
SEGGER_RTT_Write(1, &data, sizeof(data));
```

上位机中CH1会自动拆分为子通道CH1[1]和CH1[2]，各自独立显示波形，共享时间基准。

### 方式二：独立通道模式（推荐用于非同频多通道）

使用多个RTT通道（CH1~CH10），每个通道独立发送数据。MCU端代码示例：

```c
// 配置通道1
static char buf1[1024];
SEGGER_RTT_ConfigUpBuffer(1, "JScope_u4", buf1, sizeof(buf1), SEGGER_RTT_MODE_NO_BLOCK_SKIP);
// 配置通道2
static char buf2[1024];
SEGGER_RTT_ConfigUpBuffer(2, "JScope_u4", buf2, sizeof(buf2), SEGGER_RTT_MODE_NO_BLOCK_SKIP);

// 通道1发送数据
temp1 = (temp1 == 100) ? 0 : 100;
SEGGER_RTT_Write(1, &temp1, 4);

// 通道2发送数据
temp2 = (temp2 == 90) ? 10 : 90;
SEGGER_RTT_Write(2, &temp2, 1);
```

上位机中CH1和CH2各自独立显示波形，适用于不同采样频率或不同相位的场景。
